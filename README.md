# 💜 طمأنينة — Tumaanina

> **استشارات نفسية احترافية وسرّية — لتعود طمأنينتك.**
> **v1.2.0**: ثلاث عملات للعرض (دج / EUR / USD) · لوحة أخصائي بالإحصائيات والمستحقات الشهرية (عمولة 15%) · ثيم الأخضر الأطلسي · منتقي عملة في الهيدر
> منصة تجارية للاستشارات النفسية عبر الإنترنت: جلسات آمنة مع أخصائيين موثّقين — **محادثة نصية، صوتية، أو مرئية** — بأسعار واضحة **بالدينار الجزائري** وحجز فوري وست لغات.
> **v1.1.0 — بلا محفظة وبلا دفع إلكتروني**: سعر كل جلسة معروض للعميل في بطاقة الأخصائي وفي كل خطوات الحجز، ويُدفع مباشرة بين الطرفين وفق اتفاقهما — المنصة لا تمسك أي أموال.
> هذه نسخة مستقلة تماماً عن أي منصة أخرى — هوية وبيانات وتسمية الكود كلها خاصة بطمأنينة.

| 📸 **صورة شخصية للمختص** | اختيارية عند التسجيل وتظهر للعميل في الدليل واختيار المختص — تغييرها أو حذفها من الإعدادات في أي وقت |
| 💗 **صفحة شكر وعرفان** | متاحة لكل الحسابات إلى جانب الصفحات الأخرى: رموز صغيرة تطفو بهدوء في خلفية جميلة بعيداً عن النص — الأدمين يعدّل النص (بالغات الثلاث) ويغيّر نوع الرموز من تبويب مخصص |

| 🧭 **تجربة موجَّهة** | مسار من 4 خطوات للعميل: انطلاق → موضوع → اختيار الأخصائي → حجز الجلسة |

### 📱 كيف تعمل الجلسات عبر واتساب؟

1. العميل يحجز جلسة ويختار النمط: **نص** / **صوت** / **صوت وصورة**.
2. في غرفة الجلسة يظهر زر أخضر واحد: يفتح واتساب مباشرة على محادثة الأخصائي مع **رسالة تعريفية جاهزة** (الاسم المستعار، الموضوع، الموعد).
3. للنمط الصوتي: يضغط العميل زر الاتصال الصوتي 📞 أعلى المحادثة — وللمرئي: زر المكالمة المرئية 🎥.
4. **المحادثة النصية المدمجة تبقى متاحة** داخل المنصة (تعمل عبر Socket.io وتغذّي بروتوكول كشف الأزمة تلقائياً).

> رقم واتساب الأخصائي إلزامي عند تسجيله، ويُخزَّن بصيغة دولية أرقام فقط (مثال: `213555123456`).

## 🏗️ البنية التقنية

```
خادم موحّد واحد (server.js) — منفذ واحد:
├── Next.js 16 (React 19)  → الواجهة + REST API
├── Socket.io              → المحادثة النصية الفورية + الحضور + كشف الأزمة (/socket.io)
├── MongoDB (mongoose)     → قاعدة البيانات — محلية أو Atlas
└── web-push (VAPID)       → إشعارات فورية
```

### 🗄️ مجموعات قاعدة البيانات (Collections)

| المجموعة | المحتوى | أهم الحقول |
|---|---|---|
| `users` | العميلون + الأخصائيون | `role` (VICTIM/COUNSELOR/ADMIN) · `pseudonym` · `email` · `passwordHash/Salt` · `recoveryHash/Salt` (عبارة الاسترجاع) · `wilaya` |
| `counselors` | ملفات الأخصائيين المهنية | `userId` · `fullName` · `whatsapp` · `specialties[]` · `languages[]` · `diplomaImage` (base64) · `verificationStatus` (PENDING/VERIFIED/REJECTED) · `available` |
| `sessions` | جلسات الدعم | `victimId` · `counselorId` · `topic` · `mode` (TEXT/VOICE/VIDEO) · `status` · `crisisFlag` · `followUpAt` · `treatmentEnded` |
| `messages` | رسائل المحادثة النصية (تبقى محفوظة لمسار العلاج) | `sessionId` · `senderRole` · `content` · `createdAt` |
| `notifications` | إشعارات جرس الموقع الداخلية | `userId` · `key` · `title` · `body` · `read` |
| `feedbacks` | اقتراحات التطوير وبلاغات المشاكل | `type` (suggestion/bug/other/contact) · `subject` · `message` · `contact` |
| `push_subscriptions` | اشتراكات الإشعارات | `userId` · `endpoint` · `p256dh` · `auth` |
| `crisis_logs` | سجل عبارات الأزمة | `sessionId` · `source` · `phrase` · `action` |

> **ملاحظة للإدارة اليدوية**: `specialties` و`languages` مصفوفات نصية مباشرة. قيم التخصصات الصالحة: `trauma`, `grief`, `anxietyDepression`, `children`, `burnout`.

**لا بيانات تجريبية ولا حسابات افتراضية**: قاعدة البيانات تبدأ فارغة تماماً — أنت من يُدخل بياناتك الحقيقية (انظر الأسفل).

## 💻 التشغيل المحلي

المتطلبات: **Node.js 20.9+** (موصى به: 22 LTS) و**MongoDB** (محلي أو Atlas).

```bash
# 1) اعده البيئة
cp .env.example .env
#   ثم اضبط في .env:
#   MONGODB_URI=mongodb://127.0.0.1:27017/tumaanina   (أو رابط Atlas)
#   ADMIN_PASSCODE=كلمة-مرور-قوية-خاصة-بك

# 2) الاعتماديات + التشغيل
npm install
npm run dev        # → http://localhost:3020
```

للإنتاج:

```bash
npm run build
npm start          # → http://localhost:3020
```

### 👤 إدخال أخصائيين حقيقيين

**الطريقة 1 — سكربت تفاعلي (الأسرع):**

```bash
npm run db:add-counselor
# يسألك: الاسم، البريد، رقم واتساب، التخصصات، اللغات، الخبرة...
# ويطبع لك رمز الدخول فوراً لإرساله للأخصائي
# خيارات إضافية:
node scripts/add-counselor.js --list              # عرض الأخصائيين
node scripts/add-counselor.js --verify <email>    # توثيق أخصائي
node scripts/add-counselor.js --unverify <email>  # إلغاء توثيق
```

**الطريقة 2 — التسجيل الذاتي:** الأخصائي يفتح «انخراط كأخصائي» في المنصة → يملأ الاستمارة (كلمة مرور + عبارة استرجاع + رقم واتساب + **صورة الشهادة** بأي جهاز وأي حجم — تُضغط تلقائياً) → ثم توثّقه أنت من لوحة الإدارة بعد معاينة الصورة.

**الطريقة 3 — من لوحة الإدارة مباشرة:** تبويب «الحسابات» → «إنشاء حساب جديد» → أخصائي (مع توثيق فوري اختياري) أو عميل.

> الأخصائي الموثّق فقط يظهر للعملاء. العميل ينشئ حساباً دائماً: اسم مستعار يكتبه بنفسه + كلمة مرور + عبارة استرجاع — ويسجّل دخوله في كل زيارة ليجد جلساته ومحادثاته محفوظة.

### 🪟 ملاحظات Windows (PowerShell)

السكربتات متوافقة مع Windows وLinux معاً (بدون صيغ يونكس). مشاكل شائعة أثناء `npm install`:

**1) خطأ شبكة `ECONNRESET`** — انقطاع أثناء تنزيل الحزم من سجل npm:

```powershell
npm cache clean --force
npm config set fetch-retries 5
npm config set maxsockets 3
npm install
```

إن استمر الخطأ:
- جرّب شبكة أخرى (نقطة اتصال الهاتف مثلاً) أو عطّل VPN مؤقتاً.
- أو استخدم سجلاً بديلاً: `npm install --registry=https://registry.npmmirror.com`
  (أعده لاحقاً بـ `npm config delete registry`).
- إن كنت خلف بروكسي: `npm config set proxy http://127.0.0.1:PORT` و`npm config set https-proxy http://127.0.0.1:PORT`.

**2) تحذيرات `EPERM` / `cleanup Failed to remove`** — غير خطيرة: قفل ملفات من Windows Defender أو OneDrive أو محرر مفتوح. الحل الوقائي:
- أغلق VS Code وأي طرفية تستخدم مجلد المشروع، ثم أعد المحاولة.
- شغّل PowerShell **كمسؤول**.
- استثنِ مجلد المشروع من الفحص الحيّ في Windows Defender.
- تجنّب وضع المشروع داخل مجلد تتم مزامنته مع OneDrive (انقله مثلاً إلى `C:\projects\tumaanina`).
- إذا تعذر حذف `node_modules` المتبقية من محاولة فاشلة: أعد تشغيل الجهاز ثم `Remove-Item -Recurse -Force node_modules`.

### 📲 إشعارات الهاتف — التفعيل وحل المشاكل (v2.3)

> - **نظام الثيمات الحقيقي (وليس فقط نهاري/ليلي):** زر «المظهر والثيمات» يفتح نافذة فيها

>   (أزرار، بطاقات، تدرجات، رسوم، شريط جانبي) ويُحفظ في جهاز المستخدم.
> - **الإشعارات تعمل الآن في كل الحالات:** إصلاح جذري لتغيير موعد الجلسة المقبولة (كان
>   يُرفض صامتاً فلا يتغير الموعد ولا يصل إشعار)، وإشعارات جديدة للإعجاب والتعليق على
>   منشورك، والمتابعة الجديدة، والتقييم الجديد — ومراجعة كل انتقالات الجلسة: الحجز،
>   القبول، البدء، الاكتمال، الاعتذار، إلغاء العميل، تغيير الموعد، المتابعة، التذكير
>   (أصبح بست لغات كاملة بدل ثلاث).
> - **نظام تقييم المختصين (1-5 نجوم):** زر «التقييمات» الذهبي الواضح في بطاقة كل أخصائي
>   يفتح نافذة المتوسط العام وتوزيع النجوم وآخر التعليقات — وبعد كل جلسة مكتملة يقيّم
>   العميل أخصائيه من زر «قيّم الأخصائي» في جلساتي، والمتوسط يتحدث لحظياً في الملف.
> - **صفحة تمارين التهدئة:** تمرين التنفس التفاعلي + **تمرين 5-4-3-2-1** للتأريض
>   بالحواس الخمس + **المكان الآمن (الملاذ الذهني)** بالكامل، والتمارين المتاحة كلها
>   في صفحة واحدة من القائمة الجانبية — والمختص والأدمين **يضيفان تمارين جديدة** بكامل
>   تفاصيلها من نفس الصفحة مع **رفع صور توضيحية** لخطوات التنفيذ.
> - **مسح المحادثة من الطرفين:** زر مسح في نافذة التواصل يحذف الرسائل نهائياً لدى
>   الطرفين مع نافذة تأكيد.
> - **كل الأصوات مطفأة افتراضياً:** نقرات وأصوات طبيعة الخ لا تعمل إلا بعد تفعيلها
>   صريحاً من الإعدادات.
> - **زر اللغة كرة أرضية + مفتاح On/Off أنيق يقابل كل لغة** في قائمة الاختيار.
> - **أيقونة معبّرة قبل اسم كل صفحة في القائمة الجانبية** — وأيقونة صفحة الدعاء صارت
>   🤲 يدان مرفوعتين للسماء بدل القلب.
> - **نافذة التواصل تبقى في كل المراحل:** زر «تواصل» في كل جلسات العميل (مقبولة،
>   بانتظار القبول، مكتملة، ملغاة) — التواصل لا ينقطع بعد انتهاء الجلسة.

## 🚀 النشر على Railway (خطوة بخطوة)

1. **ارفع المشروع إلى GitHub**:
   ```bash
   git init && git add . && git commit -m "Tumaanina Nafsi v2.0 — MongoDB + WhatsApp"
   git branch -M main
   git remote add origin https://github.com/<حسابك>/tumaanina.git
   git push -u origin main
   ```
   (ملف `.gitignore` يستبعد `node_modules` و`.next` و`.env`.)

2. **في Railway**: `New Project` → `Deploy from GitHub repo` → اختر المستودع.
   سيكتشف Railway تلقائياً مشروع Node (عبر `package.json`) ويشغّل:
   - Build: `npm install` + `npm run build`
   - Start: `npm start` (يستمع على `PORT` الذي يضبطه Railway)

3. **المتغيرات الإلزامية** في `Variables`:
   ```
   MONGODB_URI=mongodb+srv://<user>:<pass>@<cluster>.mongodb.net/tumaanina
   ADMIN_PASSCODE=<كلمة-مرور-الإدارة>
   ```
   > أنشئ قاعدة مجانية على [MongoDB Atlas](https://www.mongodb.com/cloud/atlas) (M0) — وفي `Network Access` اسمح بالاتصال من أي IP (`0.0.0.0/0`) أو من IPs Railway.

4. **متغيرات اختيارية**:

   | المتغير | الافتراضي | الغرض |
   |---|---|---|
   | `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | توليد تلقائي + حفظ في `$DATA_DIR/vapid.json` | ثبّت إشعاراتك عبر إعادة النشر |
   | `VAPID_SUBJECT` | `mailto:stevenhacen@gmail.com` | بريد جهة الاتصال في VAPID |
   | `DATA_DIR` | `./data` | ثبّت Volume على `/data` واضبطه لحفظ مفاتيح VAPID المولدة |
   | `NEXT_PUBLIC_SOCKET_URL` | فارغ (نفس الخادم) | فقط إن فصلت خدمة المحادثة |

5. **دومين**: `Settings` → `Networking` → `Generate Domain` → ستحصل على `https://...up.railway.app`
   - HTTPS تلقائي → الإشعارات و PWA تعملان مباشرة.

6. **تحقق**: افتح `https://<نطاقك>/api` — يجب أن ترى `{"ok":true,"db":"connected",...}`.
   ثم أدخل أخصائيك الأول: `npm run db:add-counselor` من جهازك مع `MONGODB_URI` الخاص بـ Atlas، أو سجّله من واجهة المنصة ووثّقه من لوحة الإدارة.

### 💡 ملاحظة حول مفاتيح VAPID
بدون متغيرات بيئة ثابتة أو Volume، سيُعاد توليد المفاتيح عند كل إعادة نشر فتُلغى اشتراكات الإشعارات القديمة (يتعامل النظام معها تلقائياً بحذفها، لكن المستخدمين سيعيدون الاشتراك). الحل: ثبّت `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` في Railway أو استخدم Volume.

## ▲ النشر على Vercel (وضع المزامنة)

منذ v2.3.2 تعمل المحادثة النصية على **كل المنصات** بفضل فصل طبقة النقل:

| المنصة | إرسال الرسائل | استلام الرسائل | مؤشر الحضور والكتابة |
|---|---|---|---|
| **Railway** (خادم موحّد) | REST `POST /api/messages` | فوري عبر Socket.io (جسر نفس العملية) | ✔ كامل |
| **Vercel** (serverless) | REST `POST /api/messages` | وضع مزامنة — استقصاء كل 4 ثوانٍ | ✖ (طبيعي في هذا الوضع) |

**لماذا؟** بنية Vercel serverless لا تدعم إبقاء اتصالات WebSocket حيّة، لذا كان `socket.io` يفشل هناك. الآن يرسل العميل رسائله عبر REST دائماً (مضمون في كل مكان)، ويحاول Socket.io كـ«أفضل جهد»، وعند تعذر الاتصال يتحول تلقائياً للاستقصاء — مع شريط أزرق يخبر المستخدم بلطف: «وضع المزامنة — قد تتأخر الرسائل ثوانٍ قليلة».

### خيار الترقية: محادثة فورية على Vercel أيضاً
وجّه عميل Socket.io في Vercel نحو خادم Railway (CORS مفتوح أصلاً):
1. في Vercel → `Settings` → `Environment Variables` أضف:
   ```
   NEXT_PUBLIC_SOCKET_URL=https://tumaanina-annafsi-production.up.railway.app
   ```
2. **أعد النشر** (المتغيرات المسبوقة بـ `NEXT_PUBLIC_` تُدمج وقت البناء).
3. النتيجة: إرسال REST (لا يفشل أبداً) + استلام فوري عبر غرف Socket.io على Railway.

> **إن كنت تستخدم `NEXT_PUBLIC_API_URL`** (وضع الوكيل من القسم السابق): طلبات REST ووضع المزامنة يعملان عبر الوكيل تلقائياً، لكن Vercel لا يمرّر ترقية WebSocket عبر الـ rewrites — لذا للمحادثة الفورية أضف `NEXT_PUBLIC_SOCKET_URL` كما أعلاه (العميل عندها يتصل بـ Railway مباشرة بدل الوكيل).

> ملاحظة: بروتوكول كشف الأزمة يعمل في الحالتين — عبر بث الخادم الموحّد على Railway، وعبر الكشف المحلي في العميل مع تسجيل الحالة في قاعدة البيانات (`crisis_logs` + `crisisFlag`).

- **توجيه الإشعارات للمقصدين (deep-link)**: النقر على أي إشعار من جرس الموقع يفتح الصفحة المرتبطة به فعلاً (جلستي، الغرفة، محادثة الإدارة…) بدل الاكتفاء بفتح الموقع، وروابط الدفع الفوري مطابقة.
- **إشعارات باتجاه اللغة RTL/LTR**: حمولة الدفع الفوري تضم `dir` و`lang` المستخرجين من لغة حساب المستقبل — إشعار الهاتف يُعرض RTL بالعربية وLTR ببقية اللغات، والسيرفس ووركر يطبق الاتجاه بأمان مع قيم افتراضية.
- **إشعار التقييم يذكر اسم العميل**: «قيّم {name} تجربتك معك…» بدل إشعار مجهول — الاسم المستعار للعميل صريح في نص الإشعار.
- **شارة «العميل في الغرفة الآن»**: نبض حضور كل 15 ثانية من الغرفة (صلاحية 35 ثانية) يظهر للأخصائي في تفاصيل بطاقة كل جلسة مقبولة قبل بدئها — يعرف من وصل فعلاً دون اتصال.
- **البدء المبكر التزامٌ للعميل**: جلسة يبدأها الأخصائي قبل موعدها تُحتسب حضورة كاملاً في تحدّي العملاء (سلسلة الالتزام) — منطق موحّد في مُحدّي العميل بمسار مزدوج (بدء مبكر أو في الموعد).
- **تعديل وحذف الرسائل**: رسالتي النصية قابلة للتعديل (PATCH مع تعقب `editedAt`) والحذف الفردي (حذف ناعم يعرض «حُذفت هذه الرسالة») — صاحب الرسالة حصراً، والرسائل القديمة قبل v1.5.0 للقراءة فقط، مع بث فوري للتعديل والحذف للطرف الآخر.
- **الرسائل الصوتية في الدردشة**: زر ميكروفون في نافذة الدردشة يسجّل برسالة ضغط مطولة/بداية-إيقاف، بمعاينة قبل الإرسال وحد أدنى للمدة، وتُرسل base64 (نوع `voice`) وتُعرض بلاعب مخصص للطرف الآخر.
- **كسر الأسطر مضمون**: فقاعات الدردشة تكسر أطول النصوص بلا مسافات (`overflow-wrap: anywhere` + كسر URL) — لا تتمدد النافذة ولا يُقتطع النص مهما كان الطول أو خلط اللغات.
- **تجاوب إطار «محادثتك جاهزة»**: إطار منصة النص في الغرفة يمرر عمودياً عند الضيق ولا يقتص أي عنصر — بأي لغة ومقاس خط (يُبنى بالفليكس مع `min-h` محفوظة).
- **جدولة الجلسة التالية من مواعيد الأخصائي حصراً**: نافذة «الجلسة التالية» عند إنهاء الجلسة تعرض فتحات الإعدادات فقط (الأيام/الساعات التي حددها المختص) مطروحاً منها المحجوز فعلاً في الأسبوعين القادمين (`taken-slots`) — لا فتحة خارج توفره ولا تعارض.
- **نافذة العميل فور الجدولة**: بعد أن يجدول الأخصائي الجلسة التالية تصل نافذة «الجلسة التالية + اختيار المزاج» للعميل فوراً (استطلاع 10 ثوانٍ) مهما كانت صفحته — لا تنتظر ولوج «لوحتي».
- **أشرطة التقييم بواقعية**: نافذة التقييمات تعرض توزيع النجوم كنسبة كل صف من إجمالي التقييمات (مثال: 3 من 4 = 75%) بدل الشريط الكامل المضلل، مع عدّاد كل صف.
- **عبارة «مرحب بك في أي وقت»**: بدل «نحن معك متى احتجنا» في خروج الجلسة/الوداع — أدفأ وأقصر ×6 لغات.
- **الفوتر بلا تكرار**: «© 2026 طمأنينة — راحة البال أقرب مما تظن 💜» (كان الاسم مكرراً مرتين).
- **القائمة الجانبية مؤطرة بالكامل**: كل صف صفحة في إطار ناعم بمساحة لمس مريحة (min-h موحدة وحشو أوسع) — ضغط دقيق على الهاتف ومظهر متناسق.
- **توثيق الأخصائيين مضمون في كل مرة**: زر التوثيق/الاعتذار في لوحة الإدارة بتغذية راجعة كاملة (تعطيل أثناء التنفيذ + رسالة نجاح/خطأ صريحة) ومنطق خادمي يرفض المعرّفات الخاطئة بـ404 ويحدّث الحالة ذرياً ويرسل إشعاراً فورياً بالنتيجة للأخصائي.
- **صياغة الأوقات بالثيم لا باللون**: «المواعيد المتاحة تظهر بلون الثيم النشط» بدل «الخضراء» — صحيحة مع أي ثيم يختاره المستخدم (13 ثيماً).
- **الاستشارة عبر واتساب (صوتية أو مرئية) والدردشة مساندة**: تصحيح كل نصوص المنصة (الهبوط، كيف-تعمل، الأسئلة، الغرفة، الحجز) لتطابق الواقع: الجلسة صوتية أو مرئية عبر واتساب مباشرة، ودردشة الغرفة النصية/الصوتية وسيلة متابعة مساندة بين الجلسات.
- **لا تحذيرات Console**: كل DialogContent في المنصة يضم DialogTitle/Description (بصرية أو sr-only) — اختفت تحذيرات «DialogContent requires a DialogTitle» عن الكونسول في كل النوافذ.
- **واجهة وتجاوب وترجمة ×6**: نصوص الجولة الجديدة (النافذة، الدردشة، الصوتي، التعديل/الحذف، الشارات، الجدولة) مترجمة كاملة بالعربية والإنجليزية والفرنسية والتركية والروسية والصينية بمفاتيح متوازنة، مع صياغات بمفردات علم النفس.
